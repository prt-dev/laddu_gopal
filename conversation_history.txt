```python
# app/core/dependency.py
def get_current_user(credentials: HTTPAuthorizationCredentials = Depends(security)):
    return verify_access_token(credentials.credentials)
```

`verify_access_token()` checks only three things:
1. Is the token's cryptographic signature valid according to `JWT_SECRET_KEY`?
2. Is `"type": "access"` present in the payload?
3. Is the expiration timestamp (`exp`) still in the future?

If those checks pass, FastAPI considers the request fully authenticated.

In the standalone scripts ([create_products.js](file:///d:/new_projects_2026_july/gita_construction/laddu_gopal/scripts/create_products.js) and [upload_product_images.js](file:///d:/new_projects_2026_july/gita_construction/laddu_gopal/scripts/upload_product_images.js)), we created a signed token using Node.js's native `crypto` module:

```javascript
function createToken(payloadData) {
  const header = { alg: "HS256", typ: "JWT" };
  const exp = Math.floor(Date.now() / 1000) + 3600 * 24; // 24 hours expiry
  const payload = { ...payloadData, type: "access", exp };

  const b64Header = Buffer.from(JSON.stringify(header)).toString("base64url");
  const b64Payload = Buffer.from(JSON.stringify(payload)).toString("base64url");
  const signContent = `${b64Header}.${b64Payload}`;

  // Generate valid HMAC SHA-256 signature using the backend's secret key
  const signature = crypto
    .createHmac("sha256", JWT_SECRET)
    .update(signContent)
    .digest("base64url");

  return `${signContent}.${signature}`;
}
```

Because the HMAC-SHA256 signature matched the backend's secret key, the backend verified it immediately as a legitimate admin session without needing a separate login step.
